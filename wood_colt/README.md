# CS 3368 — Colt Wood: Decision Tree Network Traffic Classifier

## Overview

This folder is Colt Wood's Decision Tree work for The Port Authority's network traffic classification project. The models use UNSW-NB15 to classify **normal** network flows as HTTP, DNS, SMTP, or FTP (control traffic only; `ftp-data` is excluded). This is service classification, not intrusion detection or live traffic monitoring.

**Assignment 6 improvement:** I added timing and handshake features and compared class-balanced Decision Trees on the harder S3 experiment. I selected the improved setting using five-fold cross-validation on the training data, before evaluating the official test data. The original Assignment 5 code remains available for comparison.

## How to run

This README is for the team GitHub repository. The repository stores the two official UNSW-NB15 input datasets under `data/raw/` at the **repository root**. In the separate Assignment 6 submission ZIP, copies of both CSVs are included under `wood_colt/data/` so the archive runs independently.

1. Install Python 3 and open a terminal in the `wood_colt/` directory.
2. Install the required packages and run the final model:

   ```bash
   python -m pip install -r requirements.txt
   python final_decision_tree.py
   ```

   On Windows, `py` may be used instead of `python`.

**Data path:** `traffic_common.py` automatically uses `wood_colt/data/` when the datasets are included in the submission ZIP, or the team's shared `data/raw/` folder when running from GitHub. No manual path changes are needed.

The final script saves output to `results/final_model/`. To reproduce the original Assignment 5 comparisons and figures, run `python train_decision_tree.py` separately. The original script also creates optional `.joblib` models in `results/`.

## Dataset and experiment

After filtering to normal flows and the four requested services, the main dataset contains 15,638 training records and 8,474 testing records. The **S3 experiment** removes DNS and several simpler volume and TCP sequence-number features, leaving 8,145 training and 5,406 testing records for HTTP, SMTP, and FTP.

The Assignment 6 experiment derives features from timing, jitter, handshake, RTT/duration, window and TTL-related measurements. It compares candidates using five-fold training-data cross-validation and chooses the best timing-feature candidate without choosing settings based on official test results.

## Results

| Evaluation | Accuracy | Macro F1 | Wrong predictions |
| --- | ---: | ---: | ---: |
| Assignment 5 original Decision Tree, S3 | 96.58% | 0.937 | 185 / 5,406 |
| Assignment 6 timing-feature balanced Decision Tree, S3 | **99.00%** | **0.982** | **54 / 5,406** |

The original four-service Decision Tree scored 99.93% accuracy (6 mistakes out of 8,474), but **this is a separate, easier task**. The S3 results above are the direct before/after comparison for the Assignment 6 improvement.

## Limits

The data is from a lab-generated dataset, so the results do not prove the same accuracy on live networks. Early experiments influenced the choice to investigate S3, and repeated investigation can make test results optimistic. We use `ftp` service labels only, not `ftp-data`. The original script also performs a **separate swapped train/test experiment**, using the official test CSV for training only in that extra check; it does not change the primary evaluation split.
